# PROJECT_RULES — 科研协作与长期约束

版本：V1.0 | 2026-11-13
适用项目：`dynamic_member_coalition_core`
来源：用户本轮“文档驱动、聊天决策”指令及 `STFBS_Lite_主研员交接档案_20261113_FULL_ACTUAL.md`。
性质：长期协作规则与冻结约束索引；不替代正式科研方案、独立审核或用户授权，不授予新执行权限。

## 1. 职责及权限

- 用户：科研路线、任务范围、代码修改、测试、科学计算、资源预算、正式 attempt 和 Git 操作的最终授权权。
- 主研员：研究问题、方案与增量修订、结果分析、下一步建议及执行交接；不替代独立审核员。
- 独立科研与工程审核员：独立审查科学正确性、冻结、证据、资源和结果验收。
- Codex：按用户明确授权在 Windows 本机执行并保存真实证据；不得自动重试、扩展预算、擅自改生产源码或 Git 写入。

审核 PASS、主研员建议、授权范文与工程就绪均不等于用户授权。已有授权不得机械重复申请；新权限必须由用户明确给出。生产准入保持 BLOCKED，除非后续正式授权改变。

## 2. 长期科研原则与冻结约束

- 冻结主线：A0-R → A1 → A2 → B → C → A3；A0-R/A1/A2 已获有限机制验收，不擅自重规划。科研路线 B 与辅助资源接口工程 B 不混淆。
- STFBS-Lite：合法公开决策状态、有限候选动作及条件世界、未来闭环净价值与 Minimax Regret；代理筛选不能代替高保真价值证据。区分预测失准、真实决策次优、事前风险识别、一般决策收益。
- 冻结服务合同：连续 G/Q 合格积累进度；中断、成员/角色改变可能清零。不是 Fisher 信息理论的一般结论，不擅自改为跨中断融合的服务模型。G 与 Q、真实状态与公开信念分开。
- 真实科学执行器、合法信息边界、共同可比条件、实际提交动作、原始记录、预算和失败停止必须保留。ACTUAL 是原物理仿真执行器，不是外场实测。固定轨迹无费用评价不是零费用闭环实验。
- 已完成验收不重复；不擅自启动代理优化、恢复已停止的任务、复用消费身份、补造 PASS、增加 attempt 或重跑历史实验。
- 效率优先，代码先能在本地跑起来，科学结果优先。优先最小任务本地适配，必要核验与正式科学计算可在同一次联合授权内完成；历史复用若比完整计算成本更高，优先更直接的同源实验。不得以效率为由放宽已冻结判据或资源约束。
- BLOCKER：有证据且实质影响科学正确性、可比性、因果信息边界、证据可信性、冻结、真实资源预算或安全退出；提出最小处理。LIMITATION：披露并限定结论，不自动阻断。OPTIONAL：默认不进入当前任务。

具体任务的参数、冻结 HEAD、输入、身份、预算、停止条件与验收门槛以该任务的正式已审核方案及有效授权为准；本文件不覆盖这些细节。

## 3. 文档驱动、聊天决策

聊天负责科学判断、决策、授权和差异摘要；正式文件负责可执行细节。默认不在聊天复述长篇方案、完整 Codex 指令或日志。

最小文档集合（复用现有归档及命名，不要求迁移历史材料）：

| 文档 | 职责 | 更新时机 |
|---|---|---|
| PROJECT_RULES.md | 长期协作规则、稳定科研约束 | 用户改变规则或冻结主线时 |
| PROJECT_STATE.md | 当前阶段、科学结论、未完成任务、消费状态、冻结与下一步 | 实质状态变化时 |
| 已有正式方案及增量修订 | 任务科学设计、冻结参数、预算、验收与停止 | 必要修改时；保留旧版 |
| 独立审核意见 | 审核结论及必须吸收的修订 | 实际审核时 |
| 用户授权原文或可访问记录 | 明确任务、范围及资源权限 | 用户明确授权时；不得由代理代签 |
| 简短执行交接（必要时） | 文件路径、版本、实施补充与入口 | 方案已审且授权后，仅在需要时 |
| 任务原始归档 | 原始结果、日志、审计、资源账本、消费和状态 | Codex 实际执行时 |

正式文档使用 Markdown/TXT 为默认。聊天提供科研目标、实质变更、执行范围、预期交付、文件链接；结果则提供科学结论、最终状态、实质问题、资源摘要及证据路径。若用户需要查看详细内容，可按需展开。

## 4. 引用式执行与增量修订

- 正式方案已审核且授权时，Codex 直接读取该方案、适用审核意见、用户授权原文及长期规则；不再复制方案全文生成另一个近似版本。仅补充不可由正式文档推出的实现细节、路径、入口与审核要求。
- 新方案或修订版需有明确任务 ID、版本、来源、适用的旧版及实质变化；聊天只汇报差异。若审核补充很小且不改变方案或授权范围，可以保留原方案版本并记录准确补充依据，不人为制造版本循环。保留旧版和失败记录，不覆盖历史事实。
- 给 Codex 的引用必须指向其实际可读取的文件，写清精确路径（本机绝对路径或带明确根目录的相对路径）、版本、必要时冻结摘要及入口。聊天附件链接不等于 Windows 本机路径。不得写“继承之前要求”而无可访问来源。
- 授权可由用户本人聊天原文保存为文件；必须与原文一致，标明来源，不得将主研员整理文本伪装成用户授权。若执行依据缺失或冲突，仅补齐实际缺口；不重新设计、审核或授权已确定内容。必要时 Codex 在现有任务的入口核验中确认引用可读，不新增独立文档工程验收。
- 优先级：用户最新明确指令和实际授权范围；在该范围内，以实际源码/原始证据判断事实，以适用的已审核冻结方案判断执行约束。本规则及状态文件是索引/摘要，不静默改写正式依据。遇冲突报告并按权限处理。

引用式交接最小字段（仅在实际需要新交接时填写）：任务 ID / 方案路径+版本 / 审核意见路径 / 授权来源路径 / 实施补充 / 执行入口与归档路径。正式方案已有的预算和停止条件不重复，但必须可读、有效且不冲突。

## 5. Codex 回执与项目状态维护

- 原始结果、完整日志、科学与资源审计、冻结输入、实际执行身份及账本均存任务归档；不因缩短聊天而删证据。回执应提供状态、结果/价值矩阵、关键机制、失败首因与消费、实际资源摘要及证据路径；详细数据留在文件中。
- 主研员先回答“说明什么、尚未说明什么、下一步做什么”，再按需查阅原始证据。PASS_CANDIDATE 不是独立验收。失败保留合法结果与原始证据，不自动重试。
- 实质状态变化（科学结果、独立验收、冻结/授权、attempt 消费、任务失败/关闭、下一优先任务变化）更新 PROJECT_STATE.md；记录来源与未确认事项。无变化不重复生成状态文件。
- 本轮采用普通 Markdown 文件及已有任务归档，不开发文档管理程序、同步服务、复杂协议或生产基础设施。文件传递由用户现有方式完成；未建立同步前不得宣称本机已更新。
