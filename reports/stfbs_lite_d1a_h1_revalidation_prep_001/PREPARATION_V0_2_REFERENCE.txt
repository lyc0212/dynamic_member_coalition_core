# 四、强制补充 A：world.motion 唯一类型规范化边界

## 4.1 已确认的问题

当前代码：

`stfbs_d1a_model.py::nominal_world()`

创建：

```python
motions = {
    t["id"]: ...
    for t in view["targets"]
}
```

内部目标 ID 为整数。

但：

`stfbs_d1a_verify.py::verify()`

使用：

```python
result["world"]["motion"][str(j)]
```

而：

`stfbs_d1a_audit.py::service_audit()`

使用：

```python
result["world"]["motion"][j]
```

因此当前三个环节的键类型契约没有统一。

**这一问题必须在本轮解决，不能仅记录为未来待办。**

## 4.2 必须确定唯一数据契约

推荐采用以下原则：

**内存中的 MODEL 科学对象保持原整数目标 ID 规则。**

**JSON 文件保持标准 JSON 序列化结果。**

**对 JSON 重载数据的审计规范化只发生在一个明确的审计输入边界。**

Codex 必须根据真实调用关系确定最小实现。

可以采用：

- 一个专用只读审计输入适配器；
- 或等价的单一审计数据规范化入口。

不允许每个审计器各自临时、隐式转换键类型。

规范化规则必须：

1. 只作用于指定的目标 ID 映射。
2. 明确区分整数键与 JSON 字符串键。
3. 拒绝重复、歧义或非规范目标 ID。
4. 拒绝目标集合缺失或出现未知 ID。
5. 不改变目标的数值身份。
6. 不改变 motion 的位置和速度。
7. 不修改原始 `world` 对象。
8. 不修改原始 JSON 文件。
9. 不重新定义或覆盖原 `world_digest`。
10. 不改变历史来源摘要和实验身份。

如果采用只读副本进行规范化，必须确保正式科学对象与审计视图相互隔离。

不得把规范化后的内部副本重新当作新的 H1 世界身份。

## 4.3 强制纯数据测试

至少覆盖：

**TYPE-1：原始内存对象**

使用整数目标 ID 的 `world.motion`。

证明所定义的统一审计输入可正确读取。

**TYPE-2：JSON 重载对象**

将相同的合成数据进行 JSON 保存和重载。

证明字符串键能够在指定审计边界合法规范化。

**TYPE-3：数值一致性**

规范化前后位置和速度完全一致。

**TYPE-4：身份一致性**

规范化不修改原 `world_digest`、目标集合和原始数据内容。

**TYPE-5：重复身份**

人工构造整数键和字符串键混杂且可能指向同一目标的输入。

必须拒绝歧义映射。

**TYPE-6：非法目标身份**

未知、缺失或非法 ID 必须拒绝。

**TYPE-7：审计器一致性**

使用相同的规范化审计输入，证明 `verify()` 和 `service_audit()` 所需的 motion 访问契约一致。

如果完整 `verify()` 需要真实物理运行结果，只验证本轮许可范围内的数据访问与接口契约，不得使用 Mock PASS 冒充完整验证通过。

## 4.4 修改限制

优先修改纯审计接口或新增专用适配器。

如必须修改 `stfbs_d1a_verify.py`，只允许数据访问接口层面的最小变化。

不得改变：

- 物理控制公式；
- 目标运动公式；
- 原始轨迹；
- H1 世界生成；
- 目标身份；

### TYPE 验收

# 十三、准备阶段验收

## A. 类型兼容 PASS

- 唯一规范化边界明确；
- 内存和 JSON 均有确定性通过证据；
- 所有必要审计器的数据访问契约一致；
- 不改变目标身份、物理数据和 `world_digest`。

## B. 运行入口 PASS

- 默认拒绝 H1；
- 导入和帮助命令不会触发执行；
- 授权及目录检查先于任何写入或物理计算；
- 旧归档不可能被默认输出路径覆盖；
- 输出冲突能够拒绝。

## C. 审计接线 PASS

- 外部上下文在 Branch 创建前固定；
- 原运行完成的 Branch 被直接交给独立 G3 审计；
- Mock 编排与真实纯状态检查分别通过；
- 任一必要审计失败都会阻断总体 PASS；
- `verify()`、`service_audit()`、`audit()` 已明确接入未来验收链。

## D. 冻结协议 PASS

- 原 H1 初态和计划不变；
- D80/D100 R 策略不变；
- 预算为整组成对共享；
- G0—G5 验收矩阵完整；
- 新旧归档隔离；
- WLS、STEP、H1 调用均为零。

只有 A—D 全部通过，才允许输出：

**`D1_A_H1_REVALIDATION_PREP_READY_FOR_REVIEW`**

若存在阻断：

`D1_A_H1_REVALIDATION_PREP_BLOCKED`

若部分完成：

`D1_A_H1_REVALIDATION_PREP_PARTIAL`

上述状态都不表示实际 H1 已通过。

无论本轮结果如何：

**`D1_A_BLOCKED` 保持不变。**

不得输出：

- `D1_A_MODEL_PAIR_VALIDATED`
- `D1_A_ACCEPTED`
- `G0_G5_ALL_PASS`
- `H1_REVALIDATED`
